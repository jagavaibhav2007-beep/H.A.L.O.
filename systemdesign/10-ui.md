# System Design: UI / UX

Premium, Apple-like, glassmorphic. A floating companion that expands into a full workspace.

> **The full user-perspective spec lives in [`../ui_ux/`](../ui_ux/00-design-language.md)** — design language/tokens, the companion orb, workspace layout, and per-feature UX. Decisions locked there: **orb** companion, **calm-premium** motion, **left-sidebar** workspace, **voice approval except money**. This file remains the architectural view (panels ↔ processes ↔ events).

## Form factor
- **Floating companion**: small, always-present, glanceable (status + quick input + mic).
- **Expanded workspace**: enlarges into a full desktop-app window (Spotlight/Raycast-style expansion) with all panels.

## Panels
| Panel | Shows |
|---|---|
| **Chat** | conversation, streaming replies |
| **Activity feed** | live "what Halo is doing" (main events) + full historical log with **undo** |
| **Memory** | inspect/edit/delete beliefs; superseded history |
| **Tasks** | running/paused tasks, their state, pending approvals |
| **Skills** | list, trial, keep/kill; auto-made vs user-made |
| **Lane indicator** | always-visible current control lane (Fast/Takeover/Sandbox) + live desktop stream when in Lane 2/3 |

## Approval UX
- Tier-3 gate → **approval card** in-window (Approve / Deny / Edit args). When away, a **native desktop notification** brings the user back to it.

## Visual language
- Soft baby-blue gradients, royal-blue accents, frosted glassmorphism, generous spacing, smooth motion. Never chunky/cluttered.
- Theme-aware; consistent, minimal component set.

## Interaction
- Global hotkey summons/expands the window from anywhere (tray icon still present for quit/status, not the primary affordance).
- Voice and text are peers; the same activity feed reflects both.

## Data flow
- Pure view layer. All state comes from the Brain over WebSocket; UI holds no business logic (keeps the brain single-sourced).

## Failure handling
- Brain disconnect → "reconnecting" state, inputs queued locally, nothing lost.
- Long activity logs virtualized so the window stays smooth.

## Build order
- Phase 1 builds this shell with mocked Brain events so the feel is real and testable before the backend exists.
